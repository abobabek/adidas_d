# Требования

## Функциональные

**FR-01.** Продавец может создать запрос, указав артикул, размер, имя и телефон покупателя.
Проверка: запрос сохраняется и виден в списке активных запросов не позже чем через 2 секунды после подтверждения.

**FR-02.** Система присваивает запросу статус: «Новый», «Заказан», «Пришёл», «Покупатель уведомлён», «Выдан», «Отменён».
Проверка: у каждого запроса в списке отображается ровно один статус из перечня.

**FR-03.** Продавец может изменить статус запроса.
Проверка: после смены статус обновляется в списке, в истории появляется запись с датой и автором.

**FR-04.** Система ведёт историю изменений запроса.
Проверка: для запроса с тремя изменениями в истории отображаются три записи с автором и временем.

**FR-05.** Пользователь может искать запросы по артикулу, телефону и имени.
Проверка: при базе в 1000 запросов результат поиска выводится за 1 секунду.

**FR-06.** Пользователь может фильтровать список по статусу и дате создания.
Проверка: фильтр «Пришёл» показывает только запросы с этим статусом.

**FR-07.** Система показывает управляющему запросы без движения более 3 дней.
Проверка: запрос, не менявший статус 3 дня и более, попадает в раздел «Просроченные».

**FR-08.** Продавец может добавить комментарий к запросу.
Проверка: комментарий сохраняется и отображается в карточке запроса с автором и временем.

**FR-09.** Система формирует текст SMS или сообщения для покупателя при статусе «Пришёл».
Проверка: по нажатию кнопки отображается готовый текст с именем покупателя и названием товара, который можно скопировать.

**FR-10.** Управляющий может создавать и блокировать учётные записи продавцов.
Проверка: заблокированный пользователь не может войти, попытка входа возвращает ошибку.

**FR-11.** Система разграничивает права: продавец видит и меняет запросы, управляющий дополнительно управляет пользователями и видит отчёты.
Проверка: продавец при обращении к странице пользователей получает отказ доступа.

**FR-12.** Управляющий может выгрузить отчёт по запросам за период в CSV.
Проверка: файл содержит все запросы выбранного периода, число строк совпадает со списком на экране.

**FR-13.** Пользователь может отменить запрос с указанием причины.
Проверка: запрос получает статус «Отменён», причина отображается в карточке.

## Нефункциональные

**NFR-01.** Время отклика интерфейса на действие пользователя не превышает 500 мс при нагрузке до 10 одновременных сессий.

**NFR-02.** Доступность системы не менее 99% в часы работы бутика (10:00–22:00).

**NFR-03.** Пароли хранятся в виде хэша (bcrypt), передача данных только по HTTPS; телефоны покупателей недоступны неавторизованным.

**NFR-04.** Интерфейс корректно работает на экранах от 360 px по ширине и в актуальных версиях Chrome, Safari, Firefox.

**NFR-05.** Резервная копия базы создаётся ежедневно, восстановление возможно не более чем за 1 час.

## Out of scope (первая версия)
1. Интеграция с кассовой и складской системой сети.
2. Автоматическая отправка SMS и сообщений покупателям.
3. Мобильное приложение.
4. Онлайн-оплата и бронирование с предоплатой.
5. Аналитика и прогнозирование спроса.
6. Поддержка нескольких бутиков и сетевая отчётность.
